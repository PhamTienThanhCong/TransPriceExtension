# TransPrice — Architecture & Team Contract

> **TransPrice** — *See every price in your currency.* An open-source (MIT) Chrome extension (Manifest V3)
> that finds prices on any web page (`¥189`, `$1,299.99`, `12,99 €`, `189元`, `1.5万円` …) and converts them
> to the user's **home currency** (e.g. VND) automatically, plus a toolbar popup with an on/off toggle and a
> quick converter. Sister project of TransPop (same owner, same conventions).

This document is the **single source of truth** for every contributor (human or agent). If you need something
that is not here, follow the closest existing convention and write it in your final report — do **not** silently
invent a different contract.

---

## 1. Principles

1. **No build step.** Plain ES2022 / HTML / CSS. `extension/` is loaded unpacked and zipped as-is. No frameworks,
   no bundlers, **no npm dependencies** (dev tooling uses Node ≥ 22 built-ins only).
2. **MV3 rules.** No remote code, no `eval`/`new Function`, no inline `<script>`, no inline handlers (`onclick=`).
3. **Security.** Never put page/remote/user text into `innerHTML`. Use `textContent` / DOM APIs.
4. **Privacy.** The only network traffic is downloading the public rate table (no page content, no URLs, no
   identifiers are ever sent). No analytics, no remote fonts, no third-party scripts.
5. **Minimal permissions.** `storage`, `alarms` + the three rate hosts. Adding anything needs manager approval.
6. **Never break the page.** The content script must be invisible when it has nothing to do, must not throw,
   must be React/SPA-safe (§6.4) and must fully restore the page when turned off.
7. **Fast.** Pre-filter cheaply, time-slice scanning, batch mutations. A 2 000-product page must stay smooth.
8. **Accessible & localized UI.** Keyboard reachable, `aria-label` on icon buttons, visible focus, light + dark
   theme. Every user-visible string on extension pages goes through i18n (English + Vietnamese).

## 3. Settings, storage, rates

### 3.1 Settings — `chrome.storage.sync` key `settings`

Defaults + comments: `DEFAULT_SETTINGS` in `src/shared/constants.js`. Validation rules (applied by `getSettings()`):

| key | valid values | invalid → |
|---|---|---|
| `enabled`, `compact`, `highlight` | boolean | default |
| `homeCurrency` | ISO code present in `TransPriceCurrencies.CURRENCIES` | `''` → guessed (below) |
| `displayMode` | `DISPLAY_MODES` | `'replace'` |
| `defaultDollar` / `defaultYen` | `AMBIGUOUS_SYMBOLS.dollar` / `.yen` | default |
| `disabledSites` | array of lowercase hostnames, deduped | `[]` |
| `siteCurrency` | `{ [hostname]: { dollar?: code, yen?: code } }`, codes from `AMBIGUOUS_SYMBOLS` | drop bad entries |
| `theme` / `uiLanguage` | `THEMES` / `UI_LANGUAGES` | `'auto'` |

**Home currency guess** (when `homeCurrency` is `''`): `TransPriceCurrencies.guessHomeCurrency([chrome.i18n.getUILanguage(), ...navigator.languages])`
→ `vi`/`vi-VN` → `VND`, `ja` → `JPY`, `en-GB` → `GBP`, `en-US`/`en` → `USD`, `de-DE` → `EUR` … fallback `USD`.

Site matching (`disabledSites`, `siteCurrency`): a rule for `taobao.com` applies to `taobao.com` and every subdomain
(`world.taobao.com`). Store hostnames lowercase without a leading `www.`.

### 3.2 Local data — `chrome.storage.local`

```ts

type RatesTable = {
  base: 'USD';
  rates: { [code: string]: number };   // units of `code` per 1 USD; uppercase ISO 4217 fiat codes only; USD = 1

  source: 'currency-api' | 'currency-api-mirror' | 'er-api' | 'snapshot';

// key 'converterState' — popup quick converter: { amount: string, from: string, to: string }
// key 'uiLanguage'     — mirror of settings.uiLanguage for synchronous i18n bootstrap
```

### 3.3 `src/shared/storage.js` (ES module, imported by the service worker and extension pages)

```js

updateSettings(patch): Promise<Settings>         // validates, writes, returns the new settings
isSiteMatch(hostname, list): boolean             // exact host or subdomain match
normalizeHostname(hostname): string              // lowercase, strip leading 'www.'

setStoredRates(table): Promise<void>
```
It imports `../shared/currency-data.js` for its side effect (sets `globalThis.TransPriceCurrencies`).

### 3.4 Rates (background)

- Fetch order: `RATE_SOURCES` (constants.js). Normalise every response to a `RatesTable` (uppercase codes, keep only
  codes in `TransPriceCurrencies.CURRENCIES`, `USD = 1`, reject tables without at least USD/EUR/CNY/JPY/VND).
- Serve stale-while-revalidate: `GET_STATE` returns the stored table immediately; if it is older than
  `LIMITS.RATES_TTL_MS` (or missing) a refresh starts in the background (one in flight at a time).
- No stored table and every source fails → serve `RATES_SNAPSHOT` (`source: 'snapshot'`) so the extension always works.
- `chrome.alarms` refresh every `LIMITS.RATES_ALARM_MINUTES`; also refresh on install/startup.
- Writing a new table to `storage.local` is how content scripts and pages learn about it (`storage.onChanged`).

### 3.5 Site activation (owner decision 2026-11-23: off by default, remembered per site)

- `siteMode: 'allowlist'` (default): conversion runs **only** on sites the user turned on. `'all'`: everywhere except
  `disabledSites` (kept as an option in Options for people who prefer the old behaviour).
- **One source of truth** — `isSiteActive(settings, hostname)` in `storage.js`:
  `settings.enabled && (siteMode === 'allowlist' ? isSiteMatch(host, enabledSites) : !isSiteMatch(host, disabledSites))`.
  The content script can't import modules: it mirrors this exact function (comment pointing here; a test keeps them equal).
- **siteKey(hostname)** (`storage.js`, mirrored in content): the registrable domain, approximated without a public-suffix
  list: lowercase, strip `www.`; IPs / `localhost` / single-label hosts as-is; otherwise the last 2 labels, or the last 3
  when the last two form a known multi-part suffix (`co.uk com.au com.vn co.jp com.cn com.hk com.tw com.sg co.kr co.nz
  com.br com.mx co.id co.th com.my com.ph co.in ac.uk gov.uk org.uk net.au edu.vn gov.vn net.vn org.vn` …).
  `s.taobao.com` → `taobao.com`; `shopee.com.vn` → `shopee.com.vn`; `item.taobao.com` is then covered too.
- `SET_SITE_ACTIVE { hostname, active }`: allowlist → `active` adds `siteKey(host)` to `enabledSites`, `!active` removes every
  rule covering the host; all → the mirror operation on `disabledSites`. Returns `{ settings }`. (Replaces `SET_SITE_DISABLED`.)
- Content script when inactive: no scanning, no observer, no DOM changes. On `GET_PAGE_INFO` it still answers
  `{ hostname, siteKey, active: false, count: 0, … }` plus a lazy, read-only `detected: { count, currencies }` computed once
  with `findPrices` over `document.body.textContent` (capped at 200 000 chars, cached until the URL changes) so the popup
  can say "45 CNY prices found — turn on to convert".
- Toolbar badge: active site → count; inactive site → empty (it's the normal state, no noise); global `enabled === false` → `off`.
- Command `toggle-enabled` (Alt+Shift+C) now toggles **the current site** (asks the active tab's content script for its
  hostname via `GET_PAGE_INFO`, then `SET_SITE_ACTIVE`). Description: "Turn conversion on/off for this site".
- Popup "This site" card: inactive → compact (hostname, switch off, one-line hint using `detected`); active → full card
  (count, currencies, ¥/$ selects). The global power toggle stays at the top as the master pause.

## 4. Engine (pure, Node-testable, no DOM, no `chrome.*`)

Both files are **classic scripts with no `import`/`export`** so the same file works as a content script, as a
side-effect `import` in the service worker / pages / Node tests, and in `<script src>` on dev pages. Pattern:

```js
(() => {
  'use strict';
  const api = { /* … */ };
  globalThis.TransPriceParser = Object.freeze(api);
})();
```

### 4.1 `src/shared/currency-data.js` → `globalThis.TransPriceCurrencies`

```js
CURRENCIES: { [code]: { code, decimals /* ISO minor units: VND 0, JPY 0, USD 2, KWD 3 */, symbol /* preferred display symbol */ } }
CODES: string[]                          // sorted
TOKENS: Array<{ token, currencies: string[], kind: 'code'|'symbol'|'word', prefix: bool, suffix: bool }>

                                         // '₫','đ','VND','€','£','₩','원','₹','฿','₱','₺','₽','R$','HK$','NT$','S$','C$','A$',

                                         // locale whose region uses `code`, else the currency's home locale
```

### 4.2 `src/content/parser.js` → `globalThis.TransPriceParser`

```ts
type Ctx = {                  // built once per page by resolveContext()
  dollar: string;             // what '$' means here, e.g. 'USD'
  yen: string;                // what '¥' means here, e.g. 'CNY'
  kr: string;                 // 'SEK' | 'NOK' | 'DKK' | 'ISK'
  decimal: '.' | ',' | null;  // decimal separator hint for ambiguous numbers ('1.234')
  reasons: { dollar: Reason, yen: Reason, decimal: Reason };   // Reason = 'site-pin'|'domain'|'lang'|'script'|'default'
};
type Match = {
  start: number; end: number; // offsets in the input string (raw slice = text.slice(start, end))
  raw: string;
  amount: number;             // 189, 43.65, 15000 ('1.5万'), …
  amountMax?: number;         // ranges: '¥10-20' → amount 10, amountMax 20
  currency: string;           // resolved ISO code
  token: string;              // marker as written: '¥', 'USD', '元'
  ambiguous: boolean;         // true if `currency` came from the context (bare $ / ¥ / kr)
};

resolveContext({ hostname, lang, sampleText, settings }): Ctx
quickTest(text): boolean                    // very cheap prefilter: contains a digit AND any currency token
hasToken(text): boolean                     // contains any currency token (used to start split-price climbing)
findPrices(text, ctx): Match[]              // every price inside free text, non-overlapping, left → right
parsePrice(text, ctx): Match | null         // the WHOLE string (trimmed, whitespace-normalised) is exactly one price
parseNumber(str, { currency, decimal }): number | null
convert(amount, from, to, ratesTable): number | null   // amount / rates[from] * rates[to]; null if unknown
formatMoney(value, code, { locale, compact }): string  // Intl.NumberFormat currency style, smart fraction digits
rateText(from, to, ratesTable, { locale }): string     // '1 CNY = 3.865 ₫'
```

### 4.3 Detection algorithm (summary — the full write-up with examples lives in `docs/ALGORITHM.md`)

1. **Normalise**: NBSP / narrow NBSP / thin space → space; fullwidth digits & `＄￥` → ASCII-ish equivalents for matching
   (offsets must still point into the ORIGINAL string).
2. **Tokens** sorted longest-first (`US$` before `$`, `CN¥` before `¥`); letter codes need letter boundaries
   (`USD` yes, `USDT`/`thousand` no); `đ`/`kr`/`zł` suffixes need a non-letter after them.
3. **Number grammar**: `1,234.56` · `1.234,56` · `1 234,56` · `1'234.56` · `12,34,567.89` · `189` · `.99` no;
   optional CJK/short multipliers right after the number: `万` ×1e4, `亿/億` ×1e8, `千` ×1e3, `k/K` ×1e3, `M` ×1e6,
   `tr`/`triệu` ×1e6, `tỷ` ×1e9 (Vietnamese) — multipliers only when a currency token is attached.
4. **Shapes**: `TOKEN␣?NUMBER` · `NUMBER␣?TOKEN` · `-TOKEN NUMBER` (negative ignored, keep it positive) ·
   ranges `A␣?[-–~]␣?TOKEN?␣?B` sharing one token.
5. **Separator disambiguation**: both `.` and `,` present → the last one is the decimal separator; one kind repeated →
   grouping; a single separator followed by exactly 3 digits → **grouping** (`$1,234`, `1.234 €` almost always mean 1234),
   unless `ctx.decimal` equals that character or the currency has 3 decimals (KWD/BHD…); followed by 1–2 digits → decimal.
   Domain rules only pick `$` currencies listed in `AMBIGUOUS_SYMBOLS.dollar` (so the popup select always contains them).
6. **Context** (`resolveContext`), first hit wins: per-site pin (`settings.siteCurrency`) → domain rules
   (`taobao.com tmall.com 1688.com jd.com aliexpress.com *.cn` → CNY; `*.jp amazon.co.jp rakuten.co.jp` → JPY;
   `.ca .com.au .co.nz .sg .com.hk .tw .com.mx` → their dollar) → `<html lang>` (zh-CN→CNY, zh-TW→TWD, ja→JPY, en-CA→CAD …) →
   script detection in `sampleText` (kana → JPY; Han without kana → CNY) → user default (`defaultDollar`/`defaultYen`).
7. **Skip** non-prices: a token with no adjacent number, numbers without any token, `$` followed by template syntax
   (`${`), version strings, phone numbers, and anything inside a word.

## 5. Messaging contract

All responses are envelopes: `{ ok: true, ...data }` or `{ ok: false, error: { code, message } }` (`ERROR_CODES`).
Extension pages use `send(type, payload)` from `src/shared/messaging.js`. The content script uses its own tiny
equivalent (it can't import modules). Async handlers must `return true` from the `onMessage` listener.
Message names are the `MSG` constants — the table in `constants.js` lists payload → response for each.

- `GET_STATE` → `{ settings, rates }` — the content script calls it once at start; the popup calls it on open.
- `UPDATE_SETTINGS { patch }` → `{ settings }` — used by the content script and the keyboard command; pages may also
  call `updateSettings()` from storage.js directly.
- `SET_SITE_DISABLED { hostname, disabled }`, `SET_SITE_CURRENCY { hostname, symbol, currency|null }` → `{ settings }`.
- `REPORT_COUNT { count }` from the content script → the background sets the toolbar badge **for `sender.tab.id`**.
- `GET_PAGE_INFO` (popup → content, top frame) → `{ hostname, active, count, currencies, ambiguous }` where
  `AmbiguityInfo = { symbol: 'dollar'|'yen', token: '¥', currency: 'CNY', reason: Reason, count: number }`.
  If no content script answers (chrome:// pages, tab opened before install) the popup shows a friendly notice.
- `RESCAN` → `{ count }`.

**Toolbar badge** (background): `enabled` and site active and `count > 0` → the count (`999+` cap), brand colour;
global `enabled === false` → text `off`, grey; otherwise empty. Update on `REPORT_COUNT`, on settings change and on
tab activation. **Keyboard command** `toggle-enabled` (Alt+Shift+C) flips `settings.enabled`.

Content scripts react to `chrome.storage.onChanged` (`sync.settings` → re-evaluate; `local.rates` → re-render values).

## 6. Content script (DOM)

Files load in manifest order: `currency-data.js`, `parser.js`, `scanner.js`, `render.js`, `content.js`. They share one
namespace object `globalThis.__transprice` (scanner/render attach to it; `content.js` is the entry). Guard against double
injection (`if (globalThis.__transprice?.loaded) return;`).

### 6.1 Life cycle
1. `GET_STATE` → settings + rates. Compute `active = settings.enabled && !isSiteMatch(host, disabledSites)` and the
   page context `ctx = resolveContext({ hostname, lang: <html lang>, sampleText: title + first ~3 000 chars of body text, settings })`.
2. If active: full scan of `document.body` (time-sliced), then start a `MutationObserver`.
3. On settings/rates change: restore everything, recompute, rescan (or just re-render values for a rates-only change).
4. Inactive → restore everything, disconnect the observer, report `count: 0`. Always answer `GET_PAGE_INFO`.

### 6.2 Finding candidates
- `TreeWalker(SHOW_TEXT)` over the root. Reject (FILTER_REJECT the whole subtree) `script style noscript template
  textarea input select option code pre kbd samp svg math iframe canvas`, `[contenteditable]`, `[aria-hidden="true"]`
  is OK to keep, and every node we created (`transprice-badge`, `[data-transprice-ignore]`).
- Text node with `quickTest()` → `findPrices()`:
  - exactly one match covering the whole trimmed text and the parent element's trimmed `textContent` equals it
    → **element match** on the parent;
  - otherwise → **inline match(es)** on the text node.
- **Split prices** (the Taobao / Amazon case): `¥` `43` `.` `65` in sibling spans. When a text node has `hasToken()`
  but no full match, climb up to `LIMITS.CLUSTER_MAX_DEPTH` ancestors while `textContent.length ≤ CLUSTER_MAX_CHARS`
  and the ancestor contains no block-level descendants; the **first** ancestor for which `parsePrice(textContent)`
  succeeds is an **element match**. Number-first splits (`43.65` + `元`) work the same way because the climb starts from
  the token node. Mark processed elements in a `WeakSet` so siblings don't re-trigger.
- **Fragment runs** (fallback when the climb fails). Real Taobao markup keeps non-price siblings inside the price wrapper:
  `<div class="priceWrapper"><span>¥</span><span>43</span><span>.65</span><span>5人付款</span>…</div>` — the wrapper's text
  (`¥43.655人付款`) is not a price and naive concatenation would even read `43.655`. So: a *fragment* is a text node made only
  of digits, separators, currency tokens, multipliers or whitespace; from the token node, collect the contiguous run of
  fragment text nodes (backward + forward, inside the depth-limited ancestor, stopping at the first non-fragment text node,
  at block boundaries or at `CLUSTER_MAX_CHARS`); node boundaries are hard boundaries. `parsePrice(join(run))` → match.
  Target = the run's common ancestor if its text equals the run, else the top-most nodes covering the run (replace mode
  hides each, the badge goes after the last one). Amazon's screen-reader duplicate (`.a-offscreen`) must never produce a
  second visible badge.
- Skip matches whose currency equals the home currency, or whose currency has no rate.

### 6.3 Rendering — `render.js`
- One `<transprice-badge>` element per match, with a **closed** shadow root (style isolation). `customElements` is null
  in content scripts: just `document.createElement('transprice-badge').attachShadow({ mode: 'closed' })`.
- **replace** mode — element match: hide the price *pieces* and put the badge **inside** the price's own container, so it
  keeps the shop's font, colour and size and links / table cells / flex rows stay intact. Pieces that are elements get
  `data-transprice-hidden` (`[data-transprice-hidden]{display:none!important}` via a constructable stylesheet, `<style
  data-transprice-ignore>` fallback); pieces that are text nodes get `nodeValue = ''` (original kept in a `WeakMap` and in
  the badge's `data-transprice-parts`). For split prices the badge copies the main digits' size/weight/colour.
  Inline match: rewrite the text node's `nodeValue` (original kept for restore) — **never split or remove page text
  nodes**. When the page rewrites a converted node (React), re-convert synchronously in the MutationObserver callback
  (before paint) so the original never flashes.
- **append** mode — element match: badge after the element, `≈ 730.000 ₫`, slightly smaller, muted.
  Inline match: one badge after the text node listing its conversion(s).
- `highlight` → dotted underline + faint brand tint. Badge `title` (hover): `¥189 → 730.373 ₫ · 1 CNY = 3.865 ₫ · 2026-11-22`
  (language-neutral, no i18n needed). Ranges render as `≈ 38.650 – 77.300 ₫`.
- `restoreAll()` removes every badge, every `data-transprice-hidden` and every rewritten `nodeValue`.

### 6.4 SPA / React safety & performance
- MutationObserver (`childList`, `subtree`, `characterData`): collect roots, debounce `LIMITS.SCAN_DEBOUNCE_MS`, rescan
  only those subtrees. Ignore records caused by our own nodes (and disconnect/reconnect around our own writes).
- If the page changes a converted element/text node (new price), drop its old badge and convert again. If the page
  removes a converted element, remove its orphan badge.
- Time-slice with `requestIdleCallback`/`setTimeout(0)` chunks of `LIMITS.SCAN_BUDGET_MS`. Stop at
  `LIMITS.MAX_PRICES_PER_PAGE`. Never use `innerText` in hot paths (layout).
- Report the count to the background (`REPORT_COUNT`), throttled (≤ 1 per 500 ms).

## 9. Internationalization

Source fragments `i18n/<area>.json`: `{ "key": { "en": "…", "vi": "…", "description"?: "…" } }`. Keys are prefixed by
area (`popup_…`, `options_…`, `welcome_…`, `bg_…`, `common_…`). `npm run i18n` merges them into
`extension/_locales/{en,vi}/messages.json` (never hand-edit). HTML: `data-i18n`, `data-i18n-title`,
`data-i18n-aria-label`, `data-i18n-placeholder` + `localizeDocument()`. JS: `t(key, subs)`. Currency names come from
`Intl.DisplayNames` (no i18n keys). Vietnamese copy must be natural Vietnamese, not literal translation.
